## Findings

*(evidence-grade: every claim carries the command and output that proved it)*

**F1 — the two live colour reds were ONE cause, and the cause was a table applied
twice.** `presets.tsv`'s own header has said since C25 that *"color is the REAL colour —
what `/color` fires; the panel swatch renders it through the S0 ANSI slot map in
summon.zsh (blue⇢cyan · orange⇢blue · purple⇢magenta)"* — the rig writes felikai's
intents and translates to ANSI slots at the display end. `colors.ts` still carried the
**inverse** of that map (B18's, correct when the rig wrote slot names), so the deck
translated words that had already been translated:

```
presets.tsv        builder = blue        digger = orange
INTENT_OF          blue → orange         orange → orange
cmuxColor          #9e490c (orange)      #9e490c (orange)
```

Both mantles came out orange, and the two failing tests were the two halves of one
sentence: `colors.test.ts` asserting `colourOf(rig,'builder') === FELIKAI.blue` and
`rail.test.ts`'s fork baton asserting the Builder's composed fire body carries
`#0362b2`. The fix is a deletion — `INTENT_OF` is gone and a word is an intent or it is
nothing — and it is **strictly stronger than the old assertions**: `cmuxColor('cyan')`
and `cmuxColor('magenta')` are now `null` rather than colours, because an ANSI slot name
is not a colour word on this side of the wall. Two test **fixtures** carried the stale
spelling too and were trued to the rig's (`shelf.test.ts`, `composer.test.ts` — both
pinned `['builder','cyan']`); a fixture rig that speaks a language the rig no longer
speaks is a fixture that hides the next one of these.

**F2 — `data-at` is the deck's clock, not a free attribute, and stamping a node with it
erased the node.** The first render of the v3 Works drew three nodes whose entire text
was `NaNd`. `tick(root)` in `deck-dom.ts` rewrites the `textContent` of **every**
`[data-at]` in the document once a second (that is how every age on the deck keeps
ageing), and `drawNode` had written `box.dataset['at'] = n.at` — the fold's state name.
So one second after the first paint, every node's body was replaced by
`ago(Number('landed'))`:

```
$ ago(NaN)  ->  Math.round(NaN / 86400) + 'd'  ->  "NaNd"

NODE TEXT: "NaNd"          # the whole node
count node 3  node-h 0     # the head, the bill, the ring: all gone
```

Caught by the camera on the first shot and by nothing else — **no unit test can see
this**, because the collision is between a tenant's DOM and a global sweep that runs on
a timer in a real browser. Renamed to `data-step-at`, with the reason written at the
line. The general rule for anyone adding a tenant: `data-at` is reserved, and it does
not merely add behaviour, it **replaces your element's children**.

**F3 — a repaint signature that omits a picker's state leaves half the app on the
previous choice.** Clicking a run in the Focus pane's picker changed `showing`, but
`draw()` composed the Action pane's `paint()` signature from `[building, actionState,
picked, works, usage]` — no `showing`. Focus redrew on the new run; Action kept drawing
the old one. Measured in the same first shot: Focus said `c10/rehearsal`, Action said
`barrage/crash/3000000/cut`. **This is inherited, not introduced** — the v2 tenant had
the identical omission and it was invisible because the live city carried one flow per
building, so `flowOf()` always answered the same thing. The v3 telemetry tree carries
seven runs for `agents` and the bug surfaced on the first click. Anything using
`paint(key, host, signature, draw)` must put **everything `draw` reads** in the
signature, including state the *other* pane owns.

**F4 — the knob moves the WRITE root, not the read, and that is the whole design.**
`$INBOX_DIR` redirects `inboxFile()`, which is the one seam the preview, the mint and
the append all go through; `buildingDir()`'s fence still measures the target against the
city, unchanged, because the wire still carries a real building's path and the fence is
what stops `../../etc`. The visible consequence, photographed: on a twin with the knob
set, the ISSUES **panel** renders the real building's inbox (`Drained empty (D53)`)
while the note box beside it says *"One append to
`/var/folders/…/belvedere-camera-inbox/agents/belvedere/ISSUES.md`"*. That reads odd and
it is honest — a twin renders the real city and writes to scratch — and it is the note
box's own line, so nobody has to know the knob exists to see where the bytes will land.
A future knob that moved the read as well would be a different feature (a fixture city),
and `--fixture` already is it.

**F5 — the barrage's own runs house in `agents`, and the Works is right to draw them.**
A run houses where its subject ran, through the register, which is the same join the
census makes for a live session. The barrage's fake subjects run in
`~/code/agents/summon/log/v3/barrage/**/work`, so they are `agents` runs and they crowd
the picker: 12 run logs read → 7 drawn for `agents`, three of them barrage runs of 43
and 2 steps. Nothing is wrong — the drawing says `fake:<scenario>` on every one of those
nodes and `no account — a layer-0 sandbox the run made and owns` on the run — but a
building whose engine work is a regression harness will look busier than it is. **Named,
not designed around**: the honest fixes are the engine's (a telemetry root per campaign)
or the pane's (a fake/real filter), and both are contract changes this charge does not
own. The bound is real and printed: `12 of 65 run logs read, newest first · 5 housed
elsewhere in the city`.

**F6 — `lab/b10`, `lab/b11` and `lab/b12`'s probes are now dead letters, deliberately
left standing.** They drive `/flow/<name>/arm`, `/flow/<name>/pass` and `FLOWS_DIR`,
none of which exist. `lab/` is outside the type gate (B14 F6) and outside this charge's
own grep (the DoD names `belvedere/glass` and `belvedere/camera`), and these files are

deleting them deletes a landing's proof. They retire to probe history the way `lab/p3/`'s
parsers did (README §1). Three other probes (`lab/b16`, `lab/b19`, `lab/b21`) set

and harmless. **If the Architect wants `lab/` swept, it is a sweep, not this charge.**

**F7 — the deck's own `?b=` payload grew by 44 kB and the register walk still dominates
